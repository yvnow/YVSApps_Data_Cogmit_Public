Yes. We can build an Android application that estimates the physical distance between two smartphones, provided both phones have the app installed. We can also potentially identify which direction the other phone is located and, on supported devices, estimate its distance with much better accuracy.

The interesting part is that there are already wireless technologies inside modern smartphones that can support this. However, there is an important distinction between detecting another phone and accurately measuring the distance to it.

Let's break down the technology and how we would build it.

# 1. How would the app measure distance?

There are four possible technologies.

[Distance Estimation via Bluetooth](https://images.openai.com/static-rsc-4/5JUuXsk6D4fhs8lSvOoihrJCoXdUju7o-JjPIQ4ITOd6XdKhukvmZlEdsn82E2ssU4VR6ovlPUHBOonvpzvurV51dzzVEmG7WPt_DhO3KBrTr3nR2Ko-PrhnalvFL8iLYSpwdVAnA95qBbdv4A7wFoo_8LoQTnkBjXS3KnoidaI?purpose=inline)

A. Bluetooth Low Energy (BLE)

Best for initial prototype

- Phones discover each other.
- Measure signal strength (RSSI).
- Estimate approximate distance.
- Works across many Android phones.

Accuracy: rough estimates, often several metres of error indoors.

[The Physics of Found Is How UWB Beats BLE in Smart Tags](https://images.openai.com/static-rsc-4/nLvxPaeVuREc1O7dOgPsSF2zQXvLnQOZHj4_lSGwW3FAGziguEb4PPCQLHmiAvA2P1OIWEJ3K7es6BUUfx8Q_lAkBCkPxEU6B5BZmzTtploxJXB7cYZr8uDnmUN5aZcNv6fpfd7M-MOf0OnS4oYOoTIjfMpFlD_f7zHbGVMik8A?purpose=inline)

B. Ultra-Wideband (UWB)

Best for precision

- Measures radio signal travel time.
- Can estimate distance much more accurately.
- Supported by selected smartphones.
- Some implementations also support direction finding.

Accuracy: potentially centimetre-level under suitable conditions.

[A Two-Step Fusion Method of Wi-Fi FTM for Indoor Positioning | MDPI](https://images.openai.com/static-rsc-4/HPJ5GFvwxiklSw9s3EwwHQo5EmeEr1e_Yk2Xb3kfWOFRpmwxDzpP-W_8C6mvoCiJzzDNzx0bhpUg8eHAzpdvRRwspD-GMe578ZDzQtY4D8UjXa4_ZIzvG_SM9X0m6HbMvrZTWOalltLYiNHTcEOg1mdc76t-eibuU2wo5mVdzgM?purpose=inline)

C. Wi-Fi RTT (Round Trip Time)

- Measures the round-trip time of Wi-Fi signals.
- Can estimate distance to compatible Wi-Fi access points.
- Not generally a direct phone-to-phone ranging solution.

Useful for indoor positioning infrastructure.

[Let's Learn Mobile Tech In-Depth: #4). Sensors_Part1](https://images.openai.com/static-rsc-4/KKi44BjbSpIBp7NFaMmFnlUrum-_6uedbEVWILds0V-p6rYtl7jLjSxPdMS4tapfbf3t5lvIHb4o9zsH9YCX0d7tr6rE74y0n-bMSYWUljWZa1VVEU8uGb25Oh0RDuMBlDJpwh2LeWXSez3DR2cCym3PQ09vdrKKwsfejBdUwOg?purpose=inline)

D. Sensor fusion

- Accelerometer
- Gyroscope
- Magnetometer
- Bluetooth/UWB measurements

These can help estimate movement, orientation and direction, but cannot independently measure the distance to another phone.

# 3. The important development: Android 16 has a unified ranging API

There is something particularly relevant to this project.

Android 16 introduces the Ranging module, which provides a unified API for measuring distance and position between peer devices.

It supports:

- Ultra-Wideband
- Bluetooth Channel Sounding
- Wi-Fi NAN RTT
- Bluetooth RSSI

This is significant because we don't necessarily have to implement every wireless technology independently. We can investigate the unified `RangingManager` API and query which capabilities are available on each phone.&#x20;

| Scenario                       | Expected behaviour                                              |
| ------------------------------ | --------------------------------------------------------------- |
| Same room                      | Usually easier to estimate                                      |
| Adjacent room                  | Possible, but walls affect measurements                         |
| Different floor                | Possible to detect, but distance alone won't identify the floor |
| Behind multiple walls          | Signal may become unstable                                      |
| Phone inside a closed cupboard | May still be detectable                                         |
| Phone switched off             | Cannot be detected                                              |

One important distinction:

Radio distance is not walking distance.

If a phone is 5 metres away in a straight line, but separated by a floor and several walls, the estimated distance is not necessarily 5 metres accurately.

UWB generally provides better ranging than BLE, but even UWB is affected by obstructions and multipath reflections.

We should not promise room-level identification based on distance alone.

# 7. What are the biggest technical challenges?

There are five challenges worth anticipating.

1\. Distance estimation

BLE doesn't directly tell us distance. It gives signal strength.

We can estimate distance using a propagation model:

\\[ d=10^{\frac{RSSI_0-RSSI}{10n}} \\]

Where:

- \\(RSSI_0\\): calibrated signal strength at one metre.
- \\(RSSI\\): observed signal strength.
- \\(n\\): environmental propagation factor.

The problem is that walls, furniture, human bodies and phone orientation change signal strength.

We will need filtering and calibration rather than displaying raw estimates.

2\. Different Android manufacturers

Not every Android phone supports UWB. Even when hardware exists, Android version and manufacturer implementation matter.

We should build capability detection rather than assume every phone supports every ranging technology.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://developer.android.com\&sz=32)

developer.android.com+1



3\. Background operation

Android restricts background scanning and ranging. We need to design around foreground services, battery consumption and OS restrictions.

4\. Device identification

We shouldn't simply display every Bluetooth device. The app needs to identify phones running our application and establish a trusted session.

5\. Privacy

Both users should explicitly authorize discovery and sharing. We should avoid creating an application that silently tracks other people's phones.

# 8. My recommended MVP

I would build a product called something like PhoneRadar.

Recommended first milestone

Objective: Two Android phones should discover each other and display continuously updated approximate distance.

Initial features:

1. Install the application on two phones.
2. Open the application on both.
3. Pair using a QR code.
4. Start proximity monitoring.
5. Display estimated distance.
6. Move one phone around the house.
7. Observe the distance changing.
8. Record actual versus estimated distance at different locations.

For testing, measure at 1, 2, 3, 5 and 10 metres, with line-of-sight, through walls and across floors.

Measure:

- Mean absolute distance error.
- 90th-percentile error.
- Detection success rate.
- Measurement update frequency.
- Battery consumption.

We can then compare BLE against UWB on compatible phones.

## 10. Product case-study framing

This is also a useful product analytics case.

- Hypothesis: Smartphone-to-smartphone ranging can reduce the need for dedicated Bluetooth trackers in certain indoor use cases.
- Market alternatives: Apple AirTag, Samsung SmartTag, Google-compatible trackers and UWB-based solutions.
- Economic model: Free discovery features, with potential premium multi-device management or smart-home integrations.
- Key metric: Successful device-location sessions / total initiated sessions.
- Risk: Hardware fragmentation and inconsistent indoor ranging accuracy.
